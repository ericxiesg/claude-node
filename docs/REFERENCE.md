## File layout

### Gateway

```
/opt/vpsmcp/                       vpsmcp:vpsmcp 750
  .venv/                           virtualenv
  src/vpsmcp/                      installed source
  .rollback/<timestamp>/           last 3 pre-upgrade snapshots

/etc/vpsmcp/                       root:vpsmcp 750    service can read, not write (except hosts.d/)
  vpsmcp.env                       root:vpsmcp 640    all settings
  id_ed25519                       root:vpsmcp 640    fleet private key
  id_ed25519.pub                   root:vpsmcp 644
  known_hosts                      root:vpsmcp 644
  hosts.yaml                       root:vpsmcp 640    hand-written entries
  hosts.d/                         vpsmcp:vpsmcp 750  service-writable
    n_<hash>.yaml                  vpsmcp:vpsmcp 640  one enrolled node each

/var/lib/vpsmcp/                   vpsmcp:vpsmcp 750
  oauth_signing_key.pem            600  RS256 key for access tokens
  cookie.key                       600  login session signing key
  oauth.db                         600  clients, refresh tokens, node registry
  audit.jsonl                      600  one JSON record per tool call

/etc/systemd/system/vpsmcp.service written by `vpsmcp setup` (reference copy: deploy/vpsmcp.service)
/usr/local/bin/vpsmcp              wrapper: sudo -u vpsmcp ... -m vpsmcp (`setup` runs as root)
/etc/caddy/Caddyfile               generated by `vpsmcp caddyfile`
```

`/etc/vpsmcp` stays root-owned on purpose: a compromised service process can read
the fleet key (it must, to connect) but cannot replace it, and cannot rewrite
`vpsmcp.env`. Only `hosts.d/` is writable by the service, because enrollment
writes there. The systemd unit enforces this with `ReadOnlyPaths=/etc/vpsmcp` and
`ReadWritePaths=/var/lib/vpsmcp /etc/vpsmcp/hosts.d`.

### Node

```
/home/<user>/.ssh/authorized_keys  <user>:<user> 600  gateway public key appended
/home/<user>/.vpsmcp/jobs/<job_id>/                   detached job state
  cmd.b64  meta.json  pid  pgid  stdout.log  stderr.log  exit_code
/etc/ssh/sshd_config.d/60-vpsmcp-<user>.conf          only if pubkey auth was off
```

Nothing else. No code, no private key, no certificate.

## Users and groups

| Account | Where | Shell | Purpose |
|---|---|---|---|
| `vpsmcp` | gateway | nologin | system account the daemon runs as; owns `/opt/vpsmcp`, `/var/lib/vpsmcp`, `/etc/vpsmcp/hosts.d` |
| `ops` (`VPSMCP_ENROLL_USER`) | every node | `/bin/bash` | account the gateway logs in as; no password, no sudo |
| `caddy` | gateway | nologin | created by the Caddy package |
| your login user | gateway | — | admin; only needs sudo |

The node account is created with `useradd -m`, then `usermod -p '*'`. `useradd`
leaves `!` in `/etc/shadow`, which hosts configured with `UsePAM no` treat as a
locked account and refuse even key-based logins.

Do not add the node account to `sudo`/`wheel`. The whole permission model rests
on it being unprivileged. If a specific privileged action is needed, allowlist
exactly that command:

```
ops ALL=(root) NOPASSWD: /bin/systemctl reload nginx
```

and set `sudo: true` on that host in the inventory.

## Keys and certificates

| Item | Location | Type | Rotation |
|---|---|---|---|
| Fleet SSH key | `/etc/vpsmcp/id_ed25519` | Ed25519, no passphrase | manual; replacing it orphans every enrolled node |
| Node host keys | inventory `host_key` | reported at enrollment, pinned | re-enroll the node |
| OAuth signing key | `/var/lib/vpsmcp/oauth_signing_key.pem` | RSA 2048, RS256 | replacing it invalidates live access tokens; clients recover on refresh |
| Cookie key | `/var/lib/vpsmcp/cookie.key` | 32 random bytes | replacing it logs you out of the consent page |
| TLS certificate | `/var/lib/caddy/.local/share/caddy/certificates/` | issued by Caddy | automatic, renewed ~30 days before expiry |

The SSH key has no passphrase because systemd cannot answer a prompt. It is
generated in-process during setup and written straight to disk.

TLS uses HTTP-01 by default, so port 80 must be reachable. If it is not, use
DNS-01: `vpsmcp caddyfile --dns-route53 <zone-id>`, a Caddy build with the
provider plugin, and credentials in a systemd drop-in (not in the Caddyfile,
which is world-readable).

## Ports

| Port | Listener | Exposure |
|---|---|---|
| 443 | Caddy | public |
| 80 | Caddy | public, ACME HTTP-01 only |
| 8848 | vpsmcp | 127.0.0.1 only |
| 22 | node sshd | reachable from the gateway |

## HTTP endpoints

| Path | Auth | Caller |
|---|---|---|
| `/mcp` | Bearer JWT | Claude |
| `/.well-known/oauth-protected-resource[/mcp]` | none | Claude |
| `/.well-known/oauth-authorization-server`, `/.well-known/openid-configuration` | none | Claude |
| `/oauth/register` | none (DCR) | Claude |
| `/oauth/authorize`, `/oauth/login` | password | your browser |
| `/oauth/token`, `/oauth/revoke`, `/oauth/jwks.json` | per spec | Claude |
| `/enroll/pubkey`, `/enroll/register` | enrollment gate | new nodes |
| `/enroll/install.sh`, `/enroll/uninstall.sh` | none (scripts hold no secret) | nodes |
| `/enroll/deregister` | none; a node can only remove itself (source IP + user + port) | nodes |
| `/healthz` | none | monitoring |

`--lock-anthropic` restricts the endpoints only the Anthropic backend calls to
its egress range. It must not cover `/oauth/authorize`, `/oauth/login` or
`/enroll/*`, and must not be used at all with Claude Code, which connects from
your own machine.

## Settings

All read from `/etc/vpsmcp/vpsmcp.env` (override the path with `VPSMCP_ENV_FILE`). Values are single-quoted because the
password hash contains `$`.

| Variable | Default | Notes |
|---|---|---|
| `VPSMCP_PUBLIC_URL` | — | bare domain, no path |
| `VPSMCP_MCP_PATH` | `/mcp` | resource URL = public_url + this |
| `VPSMCP_BIND_HOST` / `_PORT` | `127.0.0.1` / `8848` | |
| `VPSMCP_DATA_DIR` | `/var/lib/vpsmcp` | keys, `oauth.db`, audit log |
| `VPSMCP_INVENTORY` | `/etc/vpsmcp/hosts.yaml` | `hosts.d/` sits next to it |
| `VPSMCP_AUDIT_LOG` | `$DATA_DIR/audit.jsonl` | |
| `VPSMCP_SSH_KEY` | `/etc/vpsmcp/id_ed25519` | fleet private key |
| `VPSMCP_SSH_KEY_PASSPHRASE` | empty | only for manual runs; systemd cannot prompt |
| `VPSMCP_KNOWN_HOSTS` | `$DATA_DIR/known_hosts` | setup sets `/etc/vpsmcp/known_hosts` |
| `VPSMCP_CONNECT_TIMEOUT` | `15` | seconds |
| `VPSMCP_ADMIN_USER` | `admin` | consent page login; setup fills in your login user |
| `VPSMCP_ADMIN_PASSWORD_HASH` | — | `vpsmcp hash-password` |
| `VPSMCP_MAX_OUTPUT_BYTES` | `32000` | per-call output cap |
| `VPSMCP_MAX_FILE_BYTES` | `4000000` | file read/write cap |
| `VPSMCP_MAX_FANOUT` | `8` | hosts per `exec_many` |
| `VPSMCP_DEFAULT_TIMEOUT` / `_MAX_TIMEOUT` | `60` / `900` | seconds |
| `VPSMCP_IDLE_CONN_TTL` | `600` | SSH pool reaper |
| `VPSMCP_STRICT_HOST_KEYS` | `1` | keep it on |
| `VPSMCP_ENROLL_MODE` | `open` | `open` / `approve` / `off` |
| `VPSMCP_ENROLL_KEY` | empty | installer must pass `-k` |
| `VPSMCP_ENROLL_ALLOW_CIDRS` | empty | source restriction |
| `VPSMCP_ENROLL_USER` | `ops` | account created on nodes |
| `VPSMCP_ENROLL_SCOPES` | `fleet.read,fleet.exec,fleet.write` | new-node defaults |

## Scopes

| Scope | Grants |
|---|---|
| `fleet.read` | list hosts, host facts, read files, list dirs, logs, job status |
| `fleet.exec` | exec, exec_many, shells, start/stop jobs |
| `fleet.write` | write, delete, copy files, purge job dirs |
| `fleet.admin` | port forwarding, audit log |

Effective permission is the intersection of token scope, the host's scopes in the
inventory, and what the SSH account can actually do. Only the last is a hard
boundary. Note that `fleet.exec` implies write in practice - a shell can redirect
into a file - so the read/write split only means something for hosts that do not
grant exec.
